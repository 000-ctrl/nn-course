2020 年以后,神经网络的主角变成了大语言模型(large language model, LLM)。它没有发明新的层:仍然是矩阵乘法、反向传播和注意力。变的是数据量、参数量,以及一个极简的目标:预测下一个 token。这一章把这台机器的账本摊开:它如何在没有人工标注的情况下学习,规模为什么有效,对齐在改变什么,推理的显存和算力花在哪里,以及它为什么会一本正经地胡说。

14.1预训练:文本自己就是标签

前面章节的分类任务需要人工标注:一张图配上“猫”,一句话配上情感标签。语言模型没有这种标签。它用的是一个几乎免费的信号:把一段文本错开一位。

拿“小猫追球”举例。输入“小猫”,要求预测“追”;输入“小猫追”,要求预测“球”。整段文本不需要任何人工处理,第 t 个 token 就是第 t+1 个 token 的标签。这种自己给自己造标签的训练叫自监督学习(self-supervised learning),目标叫下一 token 预测(next-token prediction)。

一段长度为 T 的序列会产生 T-1 个监督信号。GPT-3 用了约 3000 亿个 token 训练,等价于约 3000 亿次“猜下一个词”。每个位置都算一个交叉熵(cross-entropy)损失,猜对时小、猜错时大;反向传播把梯度写回全部参数。模型见到的不是 3000 亿道人工出的题,而是 3000 亿个从文本里自动切出来的填空题。

文本进入网络前要先分词(tokenization)。主流做法是字节级 BPE(byte-level byte pair encoding,字节对编码):它从 256 个字节开始,反复把高频相邻字节片段合并成新 token,所以任何文本——包括没见过的字和二进制串——都能被表示。第 12 章 12.3 节完整拆过这个过程,这里只回顾一句。GPT-3 的词表有 50,257 个 token;一个常用汉字通常占 1—2 个 token,一个英文单词可能被切成 2—4 段。词表越大,同样一句话的 token 数越少,但输出层的矩阵也越大。

python
import numpy as np

# 已经分好词的 token 序列,每个整数是词表下标
tokens = np.array([12, 45, 7, 91, 3, 12, 45, 8, 91, 4])

x = tokens[:-1]        # 输入:第 0..T-2 个 token
y = tokens[1:]         # 标签:第 1..T-1 个 token,不需要人工标注

# 模型输出 logits:形状 (T-1, vocab_size)
logits = model(x)
logits -= logits.max(axis=1, keepdims=True)
log_probs = logits - np.log(np.exp(logits).sum(axis=1, keepdims=True))
loss = -log_probs[np.arange(len(y)), y].mean()

注意这个目标只要求“像人写的”,不要求“是真的”。训练语料里出现过的统计规律会被学走,包括事实、句法、语气,也包括偏见和错误。模型学到的是一张巨大的条件概率表:给定前文,下一个 token 最可能是什么。它没有内置的事实数据库,也没有“我不知道”这个选项——除非训练数据里恰好有大量“我不知道”的示范。

14.2规模定律:每一点损失都有价格

把参数量画在对数坐标上,损失下降得异常规则。规模定律(scaling law)把它写成幂律:

L(N) = E + A / Nα

式子里 L 是交叉熵损失,N 是参数量,E 是数据本身的不可约损失(再大的模型也降不下去),A 和 α 决定曲线多陡。演示取 E=1.69、A=406、α=0.34,在 1M 到 1T 的区间里给出和真实实验相似的数量级:1M 参数约 5.4,1B 约 2.0,7B 约 1.87,1T 约 1.72。横轴每加一格是 10 倍参数,纵轴却只降一点点——规模有效,但每一格都更贵。

数据量也要匹配。Chinchilla(2022)的结论是:在固定算力下,参数量和数据量应按约 1:20 的比例增长,即每个参数配 20 个训练 token。GPT-3 有 1750 亿参数,只训练了约 3000 亿 token,比例约 1:1.7,按这个标准是“参数太大、数据太少”;70B 的 Chinchilla 用 1.4 万亿 token,在多数评测上追平了 175B 的 GPT-3。后来的模型又反过来:Llama 3 405B 用了 15.6 万亿 token,比例约 1:38,故意“过度训练”——训练只是一次性成本,推理要服务几亿次,小模型更便宜。

训练算力有一个好用的估算:前向加反向约等于 6ND FLOPs,N 是参数量,D 是训练 token 数。GPT-3 的账是 6×1.75×10¹¹×3×10¹¹≈3.2×10²³ FLOPs。按一张 A100 约 3×10¹⁴ FLOP/s 的有效吞吐,单卡要跑三十多年;所以真实训练要用几千张卡并行。

从 7B 到 70B,参数量是 10 倍,损失只从 1.87 降到 1.77,约 0.10;但训练算力按 6ND 和 20 token/参数算,会从约 6×10²¹ 涨到 6×10²³,是 100 倍。换句话说,最后 0.1 的损失,标价是 100 倍算力。

核心规模定律不是“大力出奇迹”,而是一张报价单。它告诉你:在当前区间,把损失再压低 0.1 大约要 10 倍参数和 100 倍训练算力;如果数据和算力不跟着涨,只加参数会更快撞上收益墙。

演示的幂律曲线上,7B 扩到 70B,预测损失大约降多少?

常见误解参数翻倍,能力就翻倍。幂律描述的是平均损失,单位是 nat,不是考试分数。损失从 2.0 降到 1.9,可能在一些基准上几乎看不出差别,也可能突然多会一项技能;后一种现象常被叫作涌现(emergence)。但近年的研究发现,不少“突然出现”是因为评测指标本身是台阶状的——比如全对才算对,把连续进步压成了断崖。可靠的说法是:损失平滑下降;具体能力是否出现,要单独测。

14.3对齐:从“续写”到“助手”

预训练出来的模型只是一个高级接龙器。你问“中国的首都是哪里”,它可能续写出“中国的首都是哪里?这是一个常见问题。”因为它见过太多这样的文本。要让它回答问题,需要第二阶段:指令微调(instruction tuning),也叫监督微调(supervised fine-tuning, SFT)。做法是收集几万到几百万条“指令—回答”对,只对回答部分算损失。数据可以人工撰写,也可以由更强的模型生成后再筛选。

第三阶段是基于人类反馈的强化学习(reinforcement learning from human feedback, RLHF)。它分三步:先让标注员对同一问题的多个回答排序;再用这些偏好训练一个奖励模型(reward model),输入“问题+回答”,输出一个分数;最后用近端策略优化(proximal policy optimization, PPO)调整语言模型,让高分回答的概率上升。训练时加一个 KL 惩罚,防止模型为了骗奖励而偏离原来的语言分布太远。

RLHF 对齐的是行为,不是知识。它改变的是“面对这个请求,应该给出什么风格、什么长度、什么拒绝方式”的分布;事实仍然来自预训练语料。OpenAI 的 InstructGPT 论文里,1.3B 的指令微调加 RLHF 模型在人类偏好评测中胜过 175B 的原始 GPT-3,说明“会按人的偏好说话”和“知道得多”是两种不同的能力。后来的直接偏好优化(direct preference optimization, DPO)把奖励模型和 PPO 合并成一个分类损失,训练更简单,但目标仍是偏好。

对齐也有代价。奖励模型只是一个近似,策略会找到它的漏洞,这叫奖励黑客(reward hacking):回答变得很长、很客气,但信息量没增加。为了对齐而牺牲一点基准性能的现象叫对齐税(alignment tax)。所以现代模型通常是“预训练打底、SFT 定格式、偏好优化调行为”三段式,而不是用一个目标包打天下。

14.4LoRA:只训练一道窄缝

全量微调(full fine-tuning)要更新所有参数。以 7B 模型为例,混合精度(mixed precision,低精度算、高精度存)训练时每个参数大约要占:2 字节权重、2 字节梯度、4 字节 Adam 一阶矩、4 字节二阶矩,再加 4 字节 fp32 主权重(master weights,fp32 副本),合计约 16 字节。7×10⁹×16≈112 GB,还没算激活值和临时缓冲。一张 80GB 的卡装不下,必须切分到多卡,或把优化器状态卸载到内存。

低秩适配(low-rank adaptation, LoRA)换了一个思路:原来的权重矩阵 W(形状 d×k)完全冻结,不存梯度,也不存优化器状态;旁边加一条窄分支 ΔW=BA,其中 B 是 d×r,A 是 r×k,秩 r(rank,矩阵的独立方向数)通常取 8—64。前向变成 y=Wx+BAx。可训练参数只有 r(d+k) 个。以 d=k=4096、r=8 为例,每层 8×8192=65,536 个,而原矩阵有 4096×4096=16,777,216 个,占比 0.39%。7B 模型在所有线性层上挂 r=8 的 LoRA,可训练参数通常只有几百万到两千万,占 0.1%—0.5%。

省显存的根本原因是:原权重不需要梯度,Adam 的两个矩也不需要为它保存。显存从“参数量 ×16 字节”降到“参数量 ×2 字节(冻结的 fp16 权重)+ 适配器的小头”。训练完可以把 BA 乘上缩放系数合并进 W,推理时结构和原模型完全一样,不会多一层。这就是 LoRA 能同时做到“训练便宜”和“部署不加延迟”的原因。它属于参数高效微调(parameter-efficient fine-tuning, PEFT);同类的还有只训练最后几层、只训练偏置项等做法。

LoRA 不是万能的:它改变的是模型已有的能力,很难灌进大量新知识;要学新事实,检索或继续预训练更合适。

python
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=8, alpha=16):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad = False          # 冻结原权重
        self.A = nn.Parameter(torch.zeros(r, base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))
        nn.init.kaiming_uniform_(self.A, a=5 ** 0.5)
        self.scale = alpha / r

    def forward(self, x):
        # 低秩分支只增加 r(d+k) 个参数
        return self.base(x) + self.scale * (x @ self.A.T @ self.B.T)

14.5推理账本:权重、KV cache 与上下文

推理(inference)的显存账单由三部分组成:权重、KV 缓存(KV cache)、激活值和临时缓冲。权重最简单:N 个参数,每个占 b 字节,就是 N×b。7B 模型在 FP16 下是 14 GB,INT8 是 7 GB,INT4 是 3.5 GB。70B 在 FP16 下是 140 GB,已经超过一张 80GB 卡;INT4 约 35 GB,一张卡能放下。这就是量化(quantization)最直接的动机:用更少的比特存同样的数,换更低的显存占用和更高的带宽利用率。代价是数值精度,INT8 通常几乎无损,INT4 需要按通道缩放、混合精度等手段,激进量化会伤到长尾知识。

真正容易被忽略的是 KV cache。自回归生成时,每生成一个 token,都要让它和前面所有 token 做注意力。为了避免重复计算,把每一层每个历史 token 的 Key 和 Value 存下来,这就是 KV cache。按标准的多头注意力(multi-head attention, MHA),整个上下文(序列)的 KV cache 大小是:

MKV = 2 · L · d · T · b

L 是层数,d 是模型宽度,T 是序列长度,b 是每元素字节数;前面的 2 表示 K 和 V 各一份。这个式子是 T 个 token 的总量:每个 token 的缓存是 2·L·d·b,乘以 T 就是整个序列。7B 模型(32 层、d=4096、FP16)每个 token 约 0.5 MB,4096 个 token 就是 2.1 GB;128K 上下文就是 68.7 GB,比权重本身还大。

所以长上下文不是免费的。两个常用的缓解手段是:分组查询注意力(grouped-query attention, GQA),让多个查询头共享一组 K/V 头,8 个 KV 头对 32 个查询头就是 4 倍节省;以及把 KV cache 也量化到 INT8。上下文窗口(context window)指的是模型一次能看到的 token 上限,常见的有 8K、32K、128K、1M。它是“工作记忆”,不是永久记忆:对话超出窗口后,早期内容要么被截断,要么被摘要,要么靠外部检索重新放进来。

算力方面,生成一个 token 的前向大约需要 2N FLOPs,再加上注意力的 4×L×T×d(T 是当前上下文长度)。7B 模型在 4096 上下文、每 token 约 1.6×10¹⁰ FLOPs。这个数字听起来不大,但解码阶段每一步都要把 14 GB 的权重从显存读进计算单元,瓶颈是显存带宽而不是峰值算力。一块 2 TB/s 的卡,理论上读完权重至少要 7 ms,实际每个 token 往往要 10—30 ms,也就是每秒 30—100 个 token。

每秒能吐多少 token 只决定速度,吐哪几个 token 由解码策略(decoding strategy)决定。模型每一步给出的是整个词表上的概率分布:贪心解码取最高项,稳定但容易陷入重复;温度(temperature)把 logits 除以 T 再 softmax,T<1 让分布变尖、T>1 让它变平;top-k 只在概率最高的 k 个词里抽样;top-p(核采样,nucleus sampling)在累计概率达到 p 的最小集合里抽样,常用 p=0.9。这三个参数只改推理时的取词方式,不动权重。它们作用在最后一层输出的 logits 上,位置紧跟在 KV cache 之后——这也解释了为什么同一个模型,换一组参数就像换了一种性格。第 10 章 10.6 给过一组具体的概率换算,可以回去对照。

常见误解显存只要装得下权重就能跑。70B 模型 FP16 权重是 140 GB,已经超过一张 80GB 卡;即便用两张卡装下权重,4K 上下文的 KV cache 还要约 10 GB,批量推理时每个并发序列再各加一份。规划显存时至少按“权重 + KV cache + 20% 余量”算,不要把权重当成全部。

14.6能力与局限:幻觉、截止日期与工具

幻觉(hallucination)不是模型“故意撒谎”,而是训练目标的直接后果。下一 token 预测奖励的是“最像训练数据里会出现的下一个词”,不是“最符合事实的词”。当模型不知道答案时,它仍然会给出一个概率最高的、语法通顺的续写;RLHF 奖励的是“人类喜欢”的回答,而人类有时也喜欢自信的语气。于是模型会编出格式完美、引用具体、但根本不存在的文献。降低幻觉的工程手段有三类:给模型可检索的资料(检索增强生成,retrieval-augmented generation, RAG);允许它调用计算器、搜索、代码执行等工具(tool use),把“算”和“查”交给确定性程序;以及在提示里要求它给出处、标注不确定。

知识截止(knowledge cutoff)是另一个硬限制:模型的参数只包含训练数据截止日期之前的信息。一个 2024 年中截止的模型,问它 2025 年的新闻,它要么说不知道,要么用旧知识编一个看起来合理的答案。解决办法不是“再问一遍”,而是把最新资料放进上下文,或者接搜索工具。

提示(prompt)能改变输出,但改变的是条件分布,不是模型权重。把要求写清楚——角色、输入、输出格式、边界条件、示例——通常比反复说“认真一点”有效得多。few-shot 示例、分步要求、以及明确要求“如果信息不足就说不确定”,都是在对同一个模型施加不同的条件。

正确做法把大模型当成一个知识渊博但会自信犯错的实习生:让它起草、改写、列提纲、写代码骨架;让搜索工具提供事实,让计算器或代码执行器提供精确结果;最后一步由你核对。重要的不是“它能不能一次答对”,而是你有没有为它设计一条可验证的流程。

14.7稀疏与并行:千亿参数怎么装进机房

到这里,这一章讲的都是一个稠密 Transformer(dense Transformer):每个 token 都要经过每一层的每一个参数。参数涨到千亿以后,这条路撞上两道墙:一张卡的显存装不下,一张卡也算不完。工程上有两种互补的绕法——让每次计算只碰一小部分参数,叫稀疏(sparsity);把同一个模型切到几千张卡上,叫并行(parallelism)。

MoE:把 FFN 换成一群专家

Transformer 的一层里,注意力之后是一个前馈网络(feed-forward network, FFN),通常是“升维 4 倍、过激活、再降回”。它通常占每层参数的四分之三左右。专家混合(mixture of experts, MoE)把这个 FFN 换成 N 份独立的专家,再加一个很小的路由器(router):

y = Σi∈TopK gi(x) · Ei(x),   g(x) = softmax(Wrx)

式中 Σ(读作 sigma)是求和,· 是相乘;gi 是路由器给第 i 个专家的权重,Ei 是该专家的输出,Wr 是路由器权重,下标 i∈TopK 表示只取分数最高的 K 个。

路由器给每个 token 打分,只让分数最高的 K 个专家参与计算(常见 K=2),再把它们的输出按权重加起来。参数量按 N 份算,每个 token 的计算量只按 K 份算——这就是“稀疏”:参数很多,但每次前向只激活其中一小块。

Mixtral 8×7B 是一个能算清的例子。它每层有 8 个专家,每个 token 选 2 个;总参数 46.7B,但每个 token 只激活约 12.9B。也就是说,它占的显存接近一个 47B 的稠密模型,单 token 的计算量却接近 13B。名字里的“8×7B”是粗略叫法,不是 56B——注意力、嵌入这些层由所有专家共享。

8每层专家数
2每 token 激活专家
46.7B总参数
12.9B每 token 激活参数

代价也很具体。第一是显存:47B 的权重在 FP16 下约 93 GB,一张 80GB 卡放不下,必须切分。第二是通信:token 要被路由到不同专家所在的卡,一次 all-to-all(全交换)交换,跨节点时很贵。第三是负载不均:如果路由器把 70% 的 token 都送给同一个专家,那张卡就成了瓶颈,所以要加负载均衡损失(load-balancing loss),或在专家容量满时丢弃 token。MoE 省的是计算;显存占用更高,通信也更多。

常见误解“8×7B”等于 56B 参数,也等于 56B 的计算。两个都不对:共享层只算一次,每个 token 只走 2 个专家。判断一个 MoE 模型贵不贵,要同时看总参数(决定显存)和激活参数(决定算力),这两个数字可能差 3—4 倍。

三种并行:切 batch、切矩阵、切层

一张卡装不下,就把工作切给多张卡。切法只有三种,区别在于切的是哪一维。

方式切什么每张卡存什么解决什么问题主要代价
数据并行(data parallelism, DP)切 batch完整模型副本吞吐;梯度汇总后等效于更大的 batch每步 all-reduce(全规约)全部梯度;显存不降
张量并行(tensor parallelism, TP)切单层矩阵矩阵的一条竖条或横条单层参数放不进一张卡每层都要通信,要求 NVLink 级带宽
流水线并行(pipeline parallelism, PP)切层连续的一段层模型深度放不进一张卡流水线气泡,后面的卡等前面的段

数据并行最直观:8 张卡各拿 1/8 的 batch,各算各的梯度,最后求平均。数学上等价于把 batch 扩大 8 倍,但每张卡都要存一份完整的权重、梯度和优化器状态。7B 模型全量微调按 14.4 的账约 112 GB,8 张 80GB 卡各自都装不下——所以数据并行本身不解决显存,只解决吞吐。ZeRO(零冗余优化器)把优化器状态、梯度、参数按数据并行的 rank(进程编号,即第几张卡)切开存,需要时再 all-gather(把各卡的分片收齐拼回完整张量),才让“数据并行 + 分片”能训练大模型。

张量并行切的是单层里的矩阵。一个 4096×4096 的线性层有 1677 万个参数,按列切成 8 份,每张卡只存 4096×512,约 210 万个。前向时各算一部分再拼接,反向时要把梯度对齐。代价是每层都要通信,所以张量并行通常限制在一个节点内的 8 张卡,靠 NVLink 的高带宽撑住;跨节点做张量并行,通信会吃掉大部分收益。

流水线并行切的是层。一个 80 层的模型分成 8 段,每张卡放 10 层,数据像流水线一样从第一段流到最后一段。问题是同一时刻只有第一段在干活,后面的卡在等,这叫流水线气泡(pipeline bubble)。用 micro-batch(微批)把一个大 batch 切成很多小块,让各段尽量排满;气泡比例约为 (p−1)/(m+p−1),p 是段数,m 是 micro-batch 数。8 段、16 个 micro-batch 时气泡约 30%,32 个时降到约 18%。

为什么千亿模型三种都要用

把数字放在一起就清楚了。175B 模型按 14.4 的 16 字节/参数算,全量训练状态约 2.8 TB。一张 80GB 卡连零头都装不下;单纯数据并行,每张卡仍要 2.8 TB;单纯张量并行最多一个节点 8 卡,也只有 640 GB;单纯流水线并行可以把层摊到很多卡上,但气泡和利用率很难看。三种必须叠起来:

  1. 用张量并行把单层矩阵切开,限制在节点内,吃 NVLink 带宽。
  2. 用流水线并行把层切开,跨节点扩展,用 micro-batch 压气泡。
  3. 用数据并行复制整套“张量 + 流水线”组合,把剩余的上千张卡用满,梯度用 all-reduce 汇总。

这常被叫作 3D 并行(3D parallelism)。Megatron-Turing NLG 530B 用了 560 台 DGX A100,合计 4,480 张 80GB 卡;配置是张量并行 8、流水线并行 35、数据并行 16,8×35×16=4,480。MoE 再叠一层:专家本身用张量并行切开,不同专家放到不同节点,路由器产生的 all-to-all 成为新的通信瓶颈。所以千亿参数训练的难点从来不是“写不出模型”,而是把计算、显存、通信三者同时排进一张拓扑图。

核心稀疏回答“每次算多少”,并行回答“总共放哪”。MoE 用总参数换容量、用激活参数省算力;数据并行换吞吐,张量并行换单层容量,流水线并行换深度容量。千亿模型没有单一解法,只有把三种并行和专家路由叠在一起的工程方案。

14.8本章清单

  1. 预训练是自监督的下一 token 预测,文本自己提供标签;一个 T token 的序列贡献 T-1 个监督信号。
  2. 损失按幂律随规模下降;10 倍参数大约换 0.1 损失,代价是约 100 倍训练算力。
  3. 指令微调和 RLHF 对齐的是行为与偏好,不是事实知识。
  4. LoRA 冻结原权重、只训练低秩分支,把 7B 全量微调的 112 GB 优化器开销降到几百万可训练参数。
  5. 推理显存 = 权重 + KV cache + 余量;上下文越长,KV cache 越大,注意力算力按平方涨。
  6. MoE 用多个专家换总参数、每个 token 只激活其中 K 个:省算力,不省显存,也不省通信。
  7. 千亿模型靠 3D 并行:张量并行切单层、流水线并行切层、数据并行复制模型;通信量和流水线气泡决定实际扩展效率。
