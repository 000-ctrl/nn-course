先认脸,再认意思。公式里的符号只有两类:一类是运算,告诉你把数怎么揉,例如 Σ、∏、∂、∇、⊙;另一类是命名,告诉你这个数指的是谁,例如 xi、η、λ、α。读一个陌生公式时先把两类分开,卡住的地方会少一半。下表 36 条覆盖本书正文和附录里出现的记号,也收了几个论文里常见、本书暂未用到的写法。

§.2怎么读一个公式

拿第 03 章的均方误差(mean squared error, MSE)当样本。原式是:

L = (1/n) Σ (ŷi − yi)²

第一步,找等号左边的名字。左边是 L,loss 的首字母,读「损失」。它是一个标量:右边这一大串无论多长,最后只产出一个数。名字定了,你才知道这个公式在回答什么问题——「这批数据现在错得多离谱」,而不是「每个参数该是多少」。

第二步,读右边最外层的运算。最外层是 (1/n) 乘以 Σ。所以整个右边是「先算一堆东西,全部加起来,再除以 n」。别从最里面开始读;先抓住最外层,你才知道这个公式的主干是平均。Σ 里面是 (ŷi − yi)²,顺序是每个样本先做减法,再平方。减法先做,因为括号;平方把负号和大小一起处理掉。

第三步,看下标范围。i 是样本编号。这里的 Σ 没写下标,按上下文是从第 1 个到第 n 个。范围决定你要重复几次:有 n 个样本,括号里的动作就做 n 次。ŷ 头上的小帽子读「预测值」,它和 y 是两个不同的数。

三步合起来,公式展开成:

L = (1/n) [ (ŷ1 − y1)² + (ŷ2 − y2)² + … + (ŷn − yn)² ]

这就是全部。你不用背「均方误差」四个字,只要会按顺序念:预测减答案,平方,全部加起来,除以样本数。

片段怎么读它在做什么
L损失最终输出的那个数,越小越好
1/nn 分之一对 n 个样本取平均,不让样本多的批次天然损失大
Σ西格玛,加起来把每个样本的平方误差累加
(ŷi − yi)²预测减答案,再平方单个样本的错;平方让正负不抵消,大错被放大
i第 i 个样本下标,范围 1 到 n

等号左边是 L,loss 的首字母。先确认它是一个数,不是一组数,你才知道这个公式在算什么。

点四个按钮中的任意一个,上面的公式片段和下面的大白话会一起换。把四段按顺序点一遍,就是一次完整的公式朗读。

代入三个数验证。三个样本的误差是 0.1、−0.2、0.9。平方后是 0.01、0.04、0.81,相加得 0.86,除以 3,得到 L ≈ 0.287。若把 0.9 那个误差修到 0.3,L 变成 (0.01+0.04+0.09)/3 ≈ 0.047。两行算术,你就知道模型为什么优先修大误差。

python
import numpy as np

y_hat = np.array([2.1, 1.8, 2.9])   # 模型预测
y     = np.array([2.0, 2.0, 2.0])   # 真实答案
err   = y_hat - y                   # [0.1, -0.2, 0.9]
L     = (err ** 2).mean()           # 先平方,再平均
print(L)                            # 0.2866666666666667

换一个公式,动作完全一样。交叉熵 L = −Σc yc log pc:左边仍是标量;最外层是「求和再取负」;下标 c 遍历类别。标签是独热时,求和里只有真实类别那一项非零,所以它退化成 −log p真实类。三步走完,一个看起来更吓人的公式也就地拆开了。

§.3单位与量级

最后一块是数值。公式里的 7B、fp16、1e-3、14 GB,难点不在数学,在单位换算。先把三套单位分开:参数个数、字节、十进制前缀。混在一起看,每个数都会显得像魔法。

科学计数法。1e-3 里的 e 是 exponent,不是自然常数。1e-3 = 1×10−3 = 0.001;1e3 = 1×103 = 1000;1e9 = 10 亿。写 1e-3 只是为了少写三个零,读的时候直接读「零点零零一」。

前缀读法数值例子
k千10332k 参数 = 32,000 个
M兆,也就是百万1061M token = 100 万个
G吉,也就是十亿10914 GB = 140 亿字节
T太,也就是万亿10121T 参数 = 1 万亿个

注意 B 有两个身份。7B 里的 B 是 billion(十亿),说的是 70 亿个参数;GB 里的 B 是 byte(字节),说的是存储空间。同一个字母,一个数个数,一个数字节。看到 7B 就以为是 7 GB,是把两个 B 当成了一个。

每个参数占几个字节,由精度决定。float32 用 4 字节,float16 和 bfloat16 用 2 字节,int8 用 1 字节,int4 只用半个字节。精度越低,权重越小,代价是数值更粗糙。

7B 为什么是 14 GB。三步:7B = 7×109 个参数;fp16 每个参数 2 字节;相乘得 7×109×2 = 14×109 字节,也就是 14 GB。没有隐藏项。换成 fp32 就是 28 GB,换成 int8 就是 7 GB,同一套乘法。

严格说,14 GB 用的是十进制:1 GB = 109 字节。操作系统常按 230 算,显示约 13.0 GiB。差 7%,不是算错,是 GB 和 GiB 两套定义。买显卡、看显存时先确认工具报的是哪一种。

训练比推理贵得多。推理只需要存权重:7B 的 fp16 权重 14 GB。全量微调还要存梯度、优化器状态和 fp32 主权重:每个参数约 2 字节权重 + 2 字节梯度 + 4 字节一阶矩 + 4 字节二阶矩 + 4 字节主权重,合计约 16 字节。7×109×16 = 112 GB,还没算激活值。所以一张 80 GB 的卡装不下 7B 的全量微调,却装得下它的 fp16 推理。第 14 章会把 KV 缓存和并行策略接着算下去。

三个最容易看错的记号
  • Σ 与 ∏:一个连加,一个连乘。读出声就不会混——「西格玛,加起来」「派,乘起来」。
  • |x| 与 ‖x‖:前者是一个数的绝对值,后者是一个向量的长度。向量没有「去掉负号」这回事。
  • 7B 与 7 GB:前者是 70 亿个参数,后者是 70 亿字节。中间差着一个「每个参数占几字节」。
