矩阵与张量

看清形状,把一层神经网络的计算读成一排神经元同时做点积。

读前第 01 章的 1.2 加权和 z = w·x + b 与 1.3 点积:知道一行权重和输入逐个相乘再相加是什么意思。可跳过2.5 的几何解释、2.6 的显卡细节和两段代码块,跳过不影响形状主线。

神经网络里跑得最多的运算不是激活函数,而是矩阵乘法。一个 768 维的向量送进 3072 个神经元,本质是一次 3072×768 的矩阵乘向量;32 个样本一起送进去,就变成 (32,768) 乘 (768,3072) 的矩阵乘法。这一章只解决一件事:给你任意一个形状,你能立刻说出它经过一层之后变成什么,以及为什么显卡特别擅长做这件事。

2.1三种容器:向量、矩阵、张量

先认清装数字的容器。标量(scalar)是一个数,比如 3.14。向量(vector)是一列数,比如 [1.0, 0.5, -1.0]。矩阵(matrix)是一张二维表,有行(row)也有列(column)。张量(tensor)是任意维的数组,向量和矩阵都是它的特例:向量是 1 维张量,矩阵是 2 维张量。深度学习框架里的“张量”没有神秘含义,它就是一块按固定形状排好的数字,外加一份记录怎么求导的元数据。

形状(shape)是一串整数,按轴(axis)的顺序写出每一维的长度。3 个数的向量,形状是 (3,),注意末尾那个逗号,它说明这是 1 维而不是一个数。3 行 4 列的矩阵,形状是 (3, 4)。32 张 3 通道 224×224 的图片堆在一起,形状是 (32, 3, 224, 224),一共 32×3×224×224 = 4,816,896 个数,按 float32(32 位浮点数,每数 4 字节)存储占 18.4 MB。索引从 0 开始:矩阵 A 的第 0 行第 2 列写作 A[0, 2],它是第 1 行的第 3 个数。

中文里的“维”有两个意思,很容易混。说“三维向量”通常指长度为 3 的向量;说“三维张量”指有 3 个轴,每个轴可以很长。读代码时不要靠中文词猜,直接看 shape。形状是这一章的主线:之后每一个报错、每一次结果不对,第一件事都是把相关张量的形状打印出来。

同一块数字可以按不同形状解释。内存里连续的 12 个数,既可以看成 3×4 的矩阵,也可以看成 2×6 的矩阵或长度 12 的向量。改变形状(reshape)通常不复制数据,只换一种索引方式。神经网络里大量使用 reshape:把 (B, C, H, W) 的特征图(每个通道一张二维图)摊平成 (B, C×H×W),再送进全连接层(每个输出都连到全部输入)。数字一个没变,但矩阵乘法现在能用了。

核心张量就是多维数组,形状是它的身份证。看到 (B, D) 要立刻读成“B 个样本,每个样本 D 个特征”,而不是“B 行 D 列的表”这么含糊。

2.2矩阵乘向量:一行就是一个神经元

一个神经元做的事是加权和。三个输入 x₁, x₂, x₃,三个权重 w₁, w₂, w₃,再加一个偏置(bias)b,输出是 w₁x₁ + w₂x₂ + w₃x₃ + b。这种“对应位置相乘、再全部加起来”的操作叫点积(dot product),结果是单个数字,不是向量。

现在放 3 个神经元,每个有自己的 3 个权重。把第 1 个神经元的权重放第 1 行,第 2 个的放第 2 行,第 3 个的放第 3 行,得到一个 3×3 的矩阵 W。矩阵乘向量 Wx 的定义,就是“每一行与 x 做一次点积”:

yi = Σj=1..3 Wij xj + bi

式中的 Σ 是求和。换成普通话:y 的第 i 个分量,只由 W 的第 i 行和 x 决定。3 个神经元、9 个权重、3 个输入,一共做 9 次乘法、6 次加法,得到 3 个输出。写成循环就是三个互不依赖的点积,谁先算谁后算都不影响结果。这是本章最重要的一句话:矩阵乘向量不是某种神秘运算,而是一排神经元同时算。矩阵的行数就是神经元个数,列数就是每个神经元看到的输入个数。

交互3×3 矩阵乘向量:逐行点积拖动三个滑块
高亮行每隔约 1.2 秒换一次。拖动滑块,三行输出会同时变化;观察每一行的点积只用到它自己和输入向量。

从列的角度看同一件事,会得到另一种直觉。把 W 按列切开,Wx 等于“输入的每一维乘以对应的一整列,再把三列加起来”。第 j 列记录的是:输入第 j 维每增加 1,所有输出分别变化多少。行视角回答“每个神经元在看什么”,列视角回答“每个输入影响谁”。两种视角算出来是同一组数字。

点开看列视角的推导

设 W = [c₁ c₂ c₃],其中 cⱼ 是第 j 列(一个长度为 3 的向量)。那么 Wx = x₁c₁ + x₂c₂ + x₃c₃。验证第 i 个分量:右边是 x₁W[i,1] + x₂W[i,2] + x₃W[i,3],正好是第 i 行与 x 的点积。这不是巧合,矩阵乘法本来就同时具备“行点积”和“列组合”两种读法。

2.3批处理:多出来的那个 B

真实训练不会一次只送一个样本,而是一次送一个小批量(mini-batch)。把 B 个样本摞起来,得到形状 (B, D) 的矩阵:第 0 个轴是样本编号,第 1 个轴是特征。一层从 D 维映射到 H 维的全连接层,权重形状是 (D, H),计算是:

(B, D) @ (D, H) → (B, H)

注意权重写成 (D, H) 而不是 (H, D),因为只有这样内层两个 D 才能对上。输出仍然是 B 行:每一行是同一个样本的新特征,每一列是一个隐藏神经元的输出。所谓“批处理”(batching),不是把 B 个样本混成一个,而是让它们在同一个矩阵乘法里各占一行,彼此不串味。这种把权重存成 (D, H)、矩阵乘写在右边的写法,和 2.2 的 Wx 差一次转置;2.7 会把两种记号并排写清楚。

算一下工作量。32 个样本、输入 768 维、输出 3072 维,一次矩阵乘法要做 32×768×3072 = 75,497,472 次“乘加”,按每次乘加 2 次浮点运算计,约 1.51 亿次浮点运算(151 MFLOP,FLOP 指一次浮点运算)。如果换成 32 次单独的矩阵乘向量,数学结果完全一样,但 32 次小任务很难喂饱显卡。合成一个 (32, 768) @ (768, 3072),显卡看到的是一块 32×3072 的输出,一次调度就能把几千个核心铺满。

批维度 B 不参与任何点积。它只是把同样的权重复制使用 B 次,所以同一批里的样本共享权重,梯度也会在这一维上求平均。这也是为什么单样本推理时通常仍保留一个长度为 1 的批维度:形状写成 (1, 768) 而不是 (768,),代码路径就和训练时完全一致,少一类形状错误。

步骤张量形状参数量

全连接 784 → 256(32, 256)200,960

2.4转置、广播与维度对齐

矩阵乘法有一条铁律:左边矩阵的列数必须等于右边矩阵的行数。满足时,结果取左边的行数和右边的列数。把 (M, K) @ (K, N) 想成“中间的 K 被夹掉,剩下 (M, N)”。上一节的 (B, D) @ (D, H) 就是这条规则的直接应用。

转置(transpose)把矩阵的行列互换,形状 (M, N) 变成 (N, M),记作 Wᵀ。它最常见的用途是凑内层维度。有些框架把全连接权重存成 (H, D),计算时写 x @ W.t();数值和 W @ x 一样,只是把存储布局换了一下。转置不是“求逆”,也不改变任何一个数,只是换索引顺序。

形状不同不能直接相加,除非其中一个能广播(broadcast)。广播的规则只有两条:先把两个形状右对齐;每一维要么相等,要么其中一个是 1,是 1 的那一维会被复制到另一边的长度。于是 (32, 3072) + (3072,) 合法:后者被看成 (1, 3072),在第 0 轴上复制 32 次;而 (32, 768) + (32, 1) 也合法,结果 (32, 768),每一行加同一个数。反过来,(32, 768) + (768, 1) 会报错:右对齐后第一维是 32 对 768,两者既不相等也没有 1。

常见误解* 不是矩阵乘法。NumPy 和 PyTorch 里 A * B 是逐元素相乘(elementwise),要求两个数组能广播到同一形状;真正的矩阵乘法是 A @ B 或 torch.matmul。把 3×3 的 W 和长度 3 的 x 写成 W * x,得到的是 W 的每一列分别乘以 x 的对应元素,而不是三个神经元的加权和。因为形状常常碰巧能广播,错误不会立刻报出来,但每个数都错了。看到结果不对,先打印 shape,再确认用的是 @ 还是 *。

把偏置加进矩阵乘法时,广播每天都在工作。权重算完得到 (B, H),偏置是 (H,),广播后每个样本加的是同一组偏置。如果偏置误写成 (B, 1),每个样本会加一个不同的数,模型仍然能训练,但你已经悄悄多了一组参数。形状检查能抓住前一种错误,抓不住后一种,所以偏置的形状要按约定写死为 (H,)。

激活值形状是 (32, 3072),偏置形状是 (3072,)。两者相加的结果形状是什么?

2.5矩阵对空间做了什么

前面把矩阵当成一排权重。换个角度,2×2 矩阵是一次平面变换:它把每个二维点 (x, y) 搬到 (ax + by, cx + dy)。单位正方形(四个角是 (0,0)、(1,0)、(1,1)、(0,1))被搬成一个平行四边形,它的面积等于行列式(determinant)的绝对值。行列式写成 ad − bc:正值说明面积被放大或缩小但方向不变,负值说明平面被翻转了一次,等于 0 说明整个平面被压成一条线,信息丢了,这个矩阵不可逆。

神经网络的每一层都是这种变换的高维版本。一个 (768, 3072) 的权重矩阵,把 768 维空间搬到 3072 维空间;如果某一层的矩阵秩(rank,独立方向数)不够,输入里就有一部分方向被彻底压掉,再深的网络也恢复不了。这也是为什么初始化不能全零:全零矩阵把一切压成原点,梯度也随之消失。

交互二维线性变换:网格、面积与行列式拖动四个元素

浅色是原始单位网格,蓝色是变换后的网格。把行列式拖到 0,看单位正方形如何塌成一条线;拖成负数,看方向标签变成“翻转”。

行列式还解释了深度学习里“可逆性”的直觉。变换的面积倍率是 |det|;如果 det 接近 0,正向计算把大量不同的输入挤到几乎同一个输出上,反向传播时梯度也会被同样地压缩,训练会变得不稳定。生成模型里有一类方法叫归一化流(normalizing flow),它要求每一层都可逆,于是必须把行列式算出来并保证它不接近 0,这正是这个几何量的工程用途。

2.6为什么 GPU 擅长矩阵乘

矩阵乘法天生适合并行。输出 (M, N) 里的每一个格子都是独立的一次点积,算 C[0,0] 不需要等 C[0,1]。一个 1024×1024 的矩阵乘,有 1,048,576 个输出格子,每个格子做 1024 次乘加,总共约 21.5 亿次浮点运算。这种“几百万个互不依赖的小任务”正是显卡的结构优势:一张 A100 有 6,912 个 FP32 核心,而一台常见的 8 核 CPU 只有 8 个通用核心,单核虽然快得多,核心数差了两个数量级。

第二个优势是内存访问规则。矩阵乘按行和列顺序读数据,地址连续、可预测,显卡可以把一块数据先搬进片上缓存,让成千上万个线程反复使用,这块技术叫分块(tiling)。A100 的显存带宽是 1,555 GB/s,双通道 DDR4 内存大约 50 GB/s,差 30 倍。对一个 1024³ 的矩阵乘,数据量约 12.6 MB,计算量 2.15 GFLOP,每读 1 字节要做约 170 次浮点运算;而 A100 的算力与带宽之比约为 12.6 FLOP/字节。计算远多于搬运,所以这类运算在显卡上是计算受限,能把核心跑满;CPU 的核心太少,往往还没算完就在等数据。

常见误解“GPU 快是因为频率高”是反的。A100 的加速频率约 1.41 GHz,比很多 CPU 的 4 GHz 低得多;它快是因为核心数量多(6,912 对 8)、显存带宽高(1,555 GB/s 对约 50 GB/s),并且愿意把大量晶体管花在并行乘加上。这也解释了为什么 GPU 对矩阵乘快得惊人,对一串必须按顺序执行的逻辑却可能比 CPU 慢:并行度用不上时,它的优势就没了。

批大小 B 在这里的作用也清楚了。B 越大,一次矩阵乘的输出格子越多,显卡越容易把所有核心铺满,单次运算的固定开销被摊薄。但 B 太大会让显存里的激活值和梯度线性增长,于是工程上要在一个范围内调:小到能放进显存,大到能让显卡忙起来。这也是“批大小”成为训练超参数的原因之一。

python
import numpy as np

W = np.array([[ 1.0, -1.0,  0.5],
              [ 0.5,  1.0, -0.5],
              [-1.0,  0.5,  1.5]])      # 形状 (3, 3)
x = np.array([1.0, 0.5, -1.0])          # 形状 (3,)

y = W @ x                               # 矩阵乘向量
print(y)                                # [ 0.   1.5 -2.25]

X = np.random.randn(32, 3)              # 32 个样本, 形状 (32, 3)
Y = X @ W.T                             # (32, 3) @ (3, 3) -> (32, 3)
print(X.shape, W.T.shape, Y.shape)      # (32, 3) (3, 3) (32, 3)

b = np.array([0.1, -0.2, 0.3])          # 形状 (3,)
Z = Y + b                               # 广播成 (32, 3)
print(Z.shape)                          # (32, 3)

# 反例: 这个加法会报错, 因为 32 和 3 无法对齐
# Y + np.zeros((3, 1))
python
import torch

W = torch.randn(3072, 768)   # 3072 个神经元, 每个 768 个权重
x = torch.randn(32, 768)     # 一批 32 个样本

y = x @ W.t()                # (32, 768) @ (768, 3072) -> (32, 3072)
b = torch.zeros(3072)
y = y + b                    # 每个样本加同一组偏置

print(y.shape)               # torch.Size([32, 3072])
print(y.dtype)               # torch.float32

2.7单样本与批量的记号约定

同一层计算,书里会出现两种写法。单样本写成 Wx + b:x 是长度 D 的列向量,W 的形状是 (out, in),每一行是一个神经元的权重,乘出来是长度 out 的列向量。批量写成 XWᵀ + b:X 把 B 个样本按行摞起来,形状 (B, D);Wᵀ 把权重转置成 (D, out),内层两个 D 对上,结果是 (B, out)。这就是 2.2 和 2.3 两种写法的关系。

关键是三个形状:X 是 (B, D),W 是 (out, in),Wᵀ 是 (D, out)。批量公式算出的第 i 行,正好等于第 i 个样本单独做 Wx + b 的结果;所谓批量,只是把 B 次单样本计算摞在一起,没有新的数学。反过来,单样本也可以补一个长度为 1 的批维度,写成 (1, D) @ (D, out),再把结果取回 (out,)。批量为 1 时,两种写法是同一个结果,只是矩阵乘写在左边还是右边。

用具体数字走一遍。设输入 3 维、输出 2 维:W = [[1, 2, 3], [4, 5, 6]],形状 (2, 3)。单样本 x = [1, 0, −1] 是 (3,),Wx 的两行分别做点积,得到 [−2, −2],形状 (2,)。现在有两个样本 X = [[1, 0, −1], [0, 2, 1]],形状 (2, 3)。直接 XW 会报错,因为内层 3 对 2 对不上;把 W 转置成 Wᵀ = [[1, 4], [2, 5], [3, 6]],形状 (3, 2),再做 (2, 3) @ (3, 2) → (2, 2)。结果第一行仍是 [−2, −2],第二行是 [7, 16]:6 个数字一个没变,变的只是 W 的行列顺序。

2.3 为了少写转置,直接把权重存成 (D, H),即 (in, out)。按本节约定,那个矩阵就是 Wᵀ,所以 2.3 的 (B, D) @ (D, H) 与 XWᵀ + b 完全等价。记住一句话:单样本 Wx + b,批量 XWᵀ + b;看到 (D, H) 的权重,先想它是不是转置过的。

2.8把形状当合同

写模型时,形状不是注释,而是接口合同。两层之间接不上,几乎永远是形状问题,不是数学问题。下面五条检查顺序能覆盖绝大多数错误。

  1. 先写下每个张量的形状,包括批维度。不要只在脑子里想,打印出来。
  2. 矩阵乘法检查内层:左边最后一维必须等于右边倒数第二维。
  3. 记住输出形状:去掉内层,保留外层。批维度 B 永远在最前面。
  4. 相加之前右对齐,逐维检查“相等或有一个是 1”。偏置写成 (H,),不要写成 (B, 1)。
  5. 结果不对时,先怀疑 * 和 @ 用错,再怀疑转置漏了,最后才怀疑公式。
正确做法在代码里养成一个习惯:每个新张量创建后打印一次 shape,或者在 PyTorch 里用 assert x.shape[-1] == W.shape[0] 把合同写成断言。报错发生在乘法之前,比算完发现数值全错再回头找要省几个小时。

最后把这一章压缩成三句话。向量是一列数,矩阵是一张表,张量是任意维的数组,形状说明每一维多长。矩阵乘向量是一排神经元各做一次点积;矩阵乘矩阵是把这件事对一批样本同时做。转置和广播只是为了把形状凑齐,真正决定结果的是内层维度是否对齐。下一章会在这个基础上问一个更关键的问题:这些权重从哪里来,以及怎样让它们自动变好。
