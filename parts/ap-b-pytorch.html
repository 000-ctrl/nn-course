B.2张量:形状、类型、设备

张量(tensor)是 PyTorch 的基本数据单位:一个多维数组,外加两个标签——数据类型(dtype)和设备(device)。形状(shape)决定它能参与哪些运算,数据类型决定每个数占几字节,设备决定它住在内存还是显存。调试 PyTorch 程序时,先打印这三个属性,通常比读十行报错更快。

三个最常见的形状约定:全连接层输入是 (batch, features);图像是 (batch, channels, height, width);序列是 (batch, time, features)。一个 32 张 RGB 图片、224×224 的批次,形状是 (32, 3, 224, 224),元素总数 32×3×224×224=4,816,896。float32 每个数占 4 字节,这一批就是 19,267,584 字节,约 18.4 MiB。换成一万张图,约 5.6 GiB,训练还没开始,数据就已经放不下。

维度顺序不是审美问题。nn.Linear 只把最后一维当特征,前面所有维度都当 batch。若你把 (32, 224, 224, 3) 直接喂进去,它会以为每个样本只有 3 个特征、一共有 32×224×224 个样本,要么报形状错误,要么算出一堆看似正常的垃圾。图像从 HWC(高×宽×通道)转到 CHW(通道×高×宽)用 permute(0, 3, 1, 2);把 28×28 拉平成 784 用 flatten(1) 或 view(x.size(0), -1)。

广播(broadcasting)让形状不同的张量也能相加。(64, 1) 加 (1, 128) 得到 (64, 128):前者沿列复制 128 份,后者沿行复制 64 份。偏置 b 的形状是 (out,),加到 (batch, out) 上时自动广播到每一行。广播只在不匹配的维度为 1 时发生,否则直接报错,不会替你猜。

view 只改变解读方式,要求张量在内存里连续;先做 permute 或 transpose 之后,张量通常不再连续,直接 view 会报 view size is not compatible with input tensor's size and stride。这时用 reshape,或者先调 .contiguous() 再 view。连续与否还影响速度:连续内存的矩阵乘法能整块读,跨步访问会让同样的计算慢上几倍。

数据类型通常用 float32。半精度 float16 或 bfloat16(16 位浮点)把显存和带宽减半,配合自动混合精度(AMP)能明显提速,但纯半精度训练容易数值不稳。类别标签必须用 int64,因为交叉熵要求标签是 long,不是 float。设备方面,模型和数据必须在同一块设备上:model.to('cuda') 之后,输入也要 .to('cuda'),否则报 Expected all tensors to be on the same device。

python
import torch

x = torch.randn(64, 3, 224, 224)      # (batch, channel, height, width)
print(x.shape, x.dtype, x.device)     # torch.Size([64, 3, 224, 224]) torch.float32 cpu

flat = x.flatten(1)                   # 每张图拉成一行
print(flat.shape)                     # (64, 150528)

b = torch.zeros(128)                  # 偏置
z = torch.zeros(64, 128) + b          # 广播成 (64, 128)
print(z.shape)                        # torch.Size([64, 128])

B.3autograd:框架替你算反向传播

自动求导(autograd)是 PyTorch 替你做的反向传播(backpropagation)。你只要把参与运算的张量标上 requires_grad=True(要求记录梯度),前向过程中的每一步都会被记进计算图(computational graph);调用 loss.backward() 时,它从损失出发沿图反向走一遍,把链式法则乘到每个叶子节点,结果写进 .grad。

用最简单的单神经元链算一遍。w=0.8,x=1.5,b=-0.2,目标 y=1。u=w·x+b=0.8×1.5-0.2=1.0; p=σ(1)=0.7311; L=-ln p=0.3133。这里 σ 是 S 型函数(sigmoid),把任意数压到 0 到 1 之间。反向时 dL/dp=-1/p=-1.368; sigmoid 的局部斜率 p(1-p)=0.1966; 两者相乘得 dL/du=-0.2689。又因为 u 对 w 的斜率是 x=1.5,所以 dL/dw=-0.2689×1.5=-0.4034; dL/db=-0.2689; dL/dx=-0.2689×0.8=-0.2151。

巧的是,sigmoid 加二元交叉熵的梯度能化简成 p-y=0.7311-1=-0.2689,正好是 dL/du。框架不会替你消掉这一项,它只是忠实地把两个局部导数乘起来;数值上你会看到 -0.2689,和手算完全一致。下面的演示把这条链画成图,你可以逐个节点看梯度怎么从右往左传;图里的 ∂L/∂w 读「偏 L 偏 w」,∂ 是偏导(partial derivative)。

python
import torch

w = torch.tensor(0.8, requires_grad=True)
x = torch.tensor(1.5)
b = torch.tensor(-0.2, requires_grad=True)

u = w * x + b
p = torch.sigmoid(u)
loss = -torch.log(p)     # 目标 y = 1,所以是 -log(p)
loss.backward()

print(u.item(), p.item(), loss.item())   # 1.0 0.7310586 0.3132617
print(w.grad.item(), b.grad.item())      # -0.4034 -0.2689
print(x.grad)                            # None:x 没标 requires_grad

三个细节决定你会不会用错。第一,.grad 是累加的,不是覆盖的;每次反向之前要清空,通常由 optimizer.zero_grad() 完成。第二,backward() 默认只能对标量调用;若损失是向量,要传 gradient 参数说明每个分量怎么加权。第三,推理时用 torch.no_grad() 或 @torch.no_grad(),否则框架仍会建图,白白吃显存。想把一个张量从图里摘出来用 .detach();想转成 Python 数字用 .item()。

新版 PyTorch 的 zero_grad 默认 set_to_none=True,直接把 .grad 设成 None,而不是写 0;下一次 backward 再分配内存,省掉一次全参数遍历,也省一块显存。若你依赖 .grad 的数值做调试,记得先判断它是否为 None。另一个小习惯:打印梯度用 .norm().item()(norm 是向量长度),不要直接 print 整个张量,几百万元素会把终端刷爆。

打开时前向值已经算好。点“反向一步”,梯度会从 L 开始,按 ∂L/∂节点 的顺序逐个出现在方框下方;边上标的是这一步的局部斜率。拖动 w、x、b 会重算前向并清空反向进度。

B.4nn.Module:层、参数与前向

nn.Module 是层的容器,也是参数的登记处。你继承它(拿父类改造出新类),在 __init__(创建对象时自动运行的初始化函数)里把层创建成属性(挂在对象上的变量,用 self 访问),在 forward(前向函数)里写数据怎么流。PyTorch 通过 __setattr__(属性赋值时自动调用的钩子)自动把 nn.Linear、nn.Conv2d 这类子模块登记进 parameters(),所以你不用手动维护参数列表。调用 model(x) 时,框架实际执行的是 model.forward(x),但不要直接调 forward,否则 hooks(钩子,插入执行的函数)之类的机制会被绕过。

算一个具体模型。输入 784 维,隐藏层 128,输出 10 类。第一层有 784×128+128=100,480 个参数,第二层有 128×10+10=1,290 个,合计 101,770 个。float32 下权重占 407,080 字节,约 398 KiB。这个数字很小,却足够在 MNIST(手写数字数据集)上做到 97% 以上的准确率。

nn.Sequential 是省略 forward 的写法:把 nn.Linear(784,128)、nn.ReLU()、nn.Linear(128,10) 依次放进一个序列。它适合直线堆叠;一旦需要残差、分支或多输入,还是老老实实写 forward。层的默认初始化也不是随便取的:Linear 和 Conv2d 都用 Kaiming uniform(按输入个数缩放的均匀分布),偏置在 [-1/√fan_in, 1/√fan_in] 内均匀采样(fan_in 是每个输出连到的输入个数,√ 是开方)。这个初始化让每层输出的方差大致保持不变,是深层网络能训练起来的前提之一。

哪些东西会被算进参数量?只有 nn.Parameter(可训练参数的包装),或者 layer.weight 这类带 requires_grad 的张量。Buffer(比如批量归一化 BatchNorm 的 running_mean)会跟着 state_dict 保存,但不算参数,也不参与梯度更新;统计模型大小时要把两者分开。想冻结预训练层,遍历它的参数设 requires_grad=False,并把这些参数从优化器里排除,否则优化器仍会维护一份用不到的状态。

查看参数量时把每个参数的 p.numel()(元素个数)加起来,不要数 state_dict() 的条目:后者包含 buffer,也不区分是否可训练。两个数字在 BatchNorm 较多的网络里能差出几千,排查显存时容易误判。

python
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self):
        super().__init__()   # 先初始化父类 nn.Module
        self.fc1 = nn.Linear(784, 128)
        self.fc2 = nn.Linear(128, 10)
        self.act = nn.ReLU()

    def forward(self, x):
        x = x.flatten(1)           # (B, 784)
        x = self.act(self.fc1(x))  # (B, 128)
        return self.fc2(x)         # (B, 10)

model = MLP()
print(model)
print(sum(p.numel() for p in model.parameters()))   # 101770

B.5Dataset 与 DataLoader

数据集(dataset)负责回答“第 i 个样本是什么”,数据加载器(data loader)负责“怎么凑成批、什么时候打乱、用几个进程读”。自定义 Dataset 只需实现两个方法:__len__ 返回样本数,__getitem__ 返回第 i 个样本的输入和标签。DataLoader 在它外面套一层,负责取样、拼批和并行预取。

具体到 MNIST:60,000 张训练图,batch_size=64,一个轮(epoch)有 ceil(60,000/64)=938 个批(ceil 是向上取整)。最后一批只有 32 张,除非设 drop_last=True。一个批的形状是 (64, 1, 28, 28),float32 下 64×784×4=200,704 字节,约 196 KiB。这个尺寸正好能塞进 CPU 缓存,预处理的开销常常比模型本身还大。

shuffle=True 只在训练集用;验证集和测试集打乱没有意义,还会让复现变麻烦。num_workers 是读数据的子进程数,0 表示在主进程读。SSD 上 2 到 4 通常够;开太多会抢 CPU,反而拖慢 GPU。用 CUDA 时 pin_memory=True 让数据页锁定,拷到显存更快。若数据已经在内存里、预处理很轻,num_workers=0 往往最快,因为省掉了进程间传数据的开销。

TensorDataset 可以直接把几个张量按第一维对齐:TensorDataset(X, Y),省掉上面的类。但如果要做数据增强、在线生成或从磁盘读图,还是自定义 Dataset。注意 __getitem__ 返回的标签类型要和损失函数匹配:CrossEntropyLoss 要 int64,MSELoss 要 float32。

python
from torch.utils.data import Dataset, DataLoader

class MyData(Dataset):
    def __init__(self, xs, ys):
        self.xs, self.ys = xs, ys
    def __len__(self):
        return len(self.xs)
    def __getitem__(self, i):
        return self.xs[i], self.ys[i]

loader = DataLoader(MyData(X, Y), batch_size=64,
                    shuffle=True, num_workers=2, drop_last=False)

xb, yb = next(iter(loader))
print(xb.shape, yb.shape, yb.dtype)
# torch.Size([64, 1, 28, 28]) torch.Size([64]) torch.int64

B.6完整训练循环模板

把前面的零件装起来,就是一个能直接跑的循环。下面这段是 MNIST 上最小可用的版本,每一行的顺序都有理由,建议先照抄,再改。真正训练时还会加学习率调度器(scheduler)、验证集早停和日志,但骨架不变。

python
import torch
import torch.nn as nn
from torch.utils.data import DataLoader

device = "cuda" if torch.cuda.is_available() else "cpu"
model = MLP().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
loader = DataLoader(train_set, batch_size=64, shuffle=True)
test_loader = DataLoader(test_set, batch_size=256, shuffle=False)

for epoch in range(10):
    model.train()                        # 打开 dropout / BatchNorm 的训练行为
    running = 0.0
    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device)
        optimizer.zero_grad()            # 清掉上一批的梯度
        logits = model(xb)               # 前向:(64, 10)
        loss = criterion(logits, yb)     # 标量
        loss.backward()                  # 反向:填充每个参数的 .grad
        optimizer.step()                 # 更新:param -= lr * grad
        running += loss.item() * xb.size(0)
    train_loss = running / len(train_set)

    model.eval()                         # 关闭 dropout,BN 用滑动统计
    correct = total = 0
    with torch.no_grad():                # 不建图,省显存
        for xb, yb in test_loader:
            xb, yb = xb.to(device), yb.to(device)
            pred = model(xb).argmax(dim=1)   # argmax 取最大值的下标
            correct += (pred == yb).sum().item()
            total += yb.size(0)
    print(f"epoch {epoch}: loss {train_loss:.4f}, acc {correct/total:.4f}")

顺序不能乱。zero_grad 必须在 backward 之前:backward 是往 .grad 里加,不是赋值。logits 是未归一化的分数,CrossEntropyLoss 内部先做 log-softmax 再取正确类的负对数,所以不要再手动加一层 softmax,否则等于做了两次。用 loss.item() 取出 Python 浮点数来累加;如果直接把 loss 张量存进列表,整张计算图会被留住,显存会随着步数一路涨。

显存不够时先把小批量(mini-batch)改小,再考虑梯度累积(gradient accumulation):把一个小批量拆成 4 份,分别 forward 和 backward,四次之后再 step() 一次。等效批大小不变,峰值显存降到约四分之一,代价是训练慢一些。学习率要按等效批大小调整,不能直接照搬小批量的数值。

model.train() 和 model.eval() 只切换行为,不改变参数。Dropout 在 train 时随机丢一部分激活,eval 时全部保留并按概率缩放;BatchNorm 在 train 时用当前批的均值方差,eval 时用训练期间累计的滑动平均。这两个层在两种模式下结果不同,所以训练前必须 train(),评估前必须 eval()。评估时还要配 no_grad:eval() 管层的行为,no_grad() 管要不要建计算图,它们是两件事。

调度器每轮调用一次 scheduler.step(),位置在 optimizer.step() 之后;顺序反了会跳过第一个学习率,新版 PyTorch 还会给出警告。日志里至少记录训练损失、验证损失和验证准确率;只看训练损失,你无法判断模型是在学习还是在背诵训练集。

B.7L2 与 weight_decay

第 7 章讲过,L2 正则化(L2 regularization)是在损失后面加 (λ/2)Σw2(λ 是惩罚强度,正则化系数),让权重每一步先缩一点。PyTorch 的优化器里有个 weight_decay 参数,名字叫权重衰减(weight decay),于是很多人默认它等于 L2。这个等式只在 SGD 下成立;换成 Adam,同样的参数做的是另一件事。

先看 SGD(随机梯度下降)。L2 项对 w 求导得到 λw,梯度下降的更新变成(其中 η 是学习率,步长;g 是梯度):

w ← w − η(g + λw) = (1 − ηλ)w − ηg

取 η=0.1、λ=0.01,每一步先把 w 乘 0.999,再减梯度。哪怕梯度一直是 0,1,000 步后 w 也只剩原来的 0.9991000≈0.368,衰减了 63%。torch.optim.SGD(..., weight_decay=0.01) 做的事就是往梯度里加 0.01×w,再做上面这步,所以它和 L2 等价,连系数含义都一致。此时不要再在 loss 里手写 L2 项,否则同一个惩罚算了两遍。

Adam 的问题出在分母。Adam(weight_decay=0.01) 把 λw 加进梯度后,整个梯度(包括这一项)要除以 √v̂——该参数梯度平方的滑动平均(二阶矩,second moment)。梯度长期很小的参数,分母小,λw 被放得很大;梯度长期很大的参数,分母大,λw 被压得很小。举个例子:某参数 w=2.0,长期梯度约 10-4,√v̂≈10-4,学习率 10-3。按真正的衰减,一步应缩 ηλw=10-3×0.01×2=2×10-5;但耦合进梯度后,实际挪动是 10-3×(0.02+10-4)/10-4≈0.2,是前者的 10,000 倍。同一个 0.01,在不同参数上的收缩强度能差出几个数量级,已经不是第 7 章那个 L2 目标了。

AdamW 把衰减拆出来:自适应那一步只用原始梯度,收缩单独乘在权重上(m̂ 是梯度的滑动平均,一阶矩;ε 是防止除零的小常数):

w ← w − η · m̂ / (√v̂ + ε) − ηλw

这样每个参数每步都按同一个 ηλ 收缩,回到 (1−ηλ)w 的形式。PyTorch 里对应 torch.optim.AdamW;写 Adam(weight_decay=...) 得到的是耦合 L2,只是名字也叫 weight_decay。第 6 章的训练循环用 AdamW、第 7 章用分组 weight_decay,原因都在这里。

python
# SGD:weight_decay 就是 L2
opt = torch.optim.SGD(model.parameters(), lr=0.1, weight_decay=1e-2)

# Adam:weight_decay 耦合进梯度,不是真正的衰减
opt = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-2)

# AdamW:解耦,通常优先
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)

最后两条习惯:偏置和 BatchNorm 的缩放参数通常不衰减,第 7 章用参数分组给它们 weight_decay=0;调 weight_decay 时按数量级试,1e-4、1e-3、1e-2、1e-1 各跑一次,不要在线性刻度上微调。它和 dropout 一样,是拿训练损失换验证损失的手段,判断依据仍然只看验证集。

B.8保存与加载

保存的首选是 state_dict:一个从参数名到张量的字典,不包含模型类本身。加载时先建一个结构相同的模型,再把字典灌进去。这个做法把“结构”和“数值”分开,结构写在代码里,数值存成文件,升级代码时清楚得多。

python
torch.save(model.state_dict(), "mnist_mlp.pt")

model = MLP().to(device)
state = torch.load("mnist_mlp.pt", map_location=device)
model.load_state_dict(state)
model.eval()

为什么不用 torch.save(model) 直接存整个对象?因为它用 pickle(Python 对象序列化工具)把类路径也写进去;换一个目录、改一次类名、升级框架,加载就可能失败。state_dict 只存数字,稳定得多。刚才那个 101,770 个参数的模型,文件约 407 KB,float32 每个参数 4 字节。

保存频率也有讲究:每个轮(epoch)存一次最新检查点,另外单独存一份最佳验证准确率的模型。只存最新,过拟合后无法回头;只存最佳,断点续训会丢掉优化器状态。两个文件加起来通常不到模型权重的两倍,却能让一次意外中断只损失一个轮(epoch)。

如果要断点续训,保存检查点(checkpoint):模型、优化器、当前轮数、最佳准确率。Adam 还有两份状态(一阶矩和二阶矩),每份和参数一样大;优化器状态不存,续训后的前几百步会和没断过不一样。map_location 决定张量加载到哪块设备,在没有 GPU 的机器上读 GPU 训练的文件时必须写。

python
ckpt = {"model": model.state_dict(),
        "optim": optimizer.state_dict(),
        "epoch": epoch,
        "best": best_acc}
torch.save(ckpt, "ckpt.pt")

ckpt = torch.load("ckpt.pt", map_location=device)
model.load_state_dict(ckpt["model"])
optimizer.load_state_dict(ckpt["optim"])
start_epoch = ckpt["epoch"] + 1

加载不可信来源的权重时用 weights_only=True(新版本默认),避免 pickle 在加载时执行任意代码。自己训练、自己保存的文件风险低,但从网上下载的 .pt 文件应当先当作可执行文件对待。

B.9三个最常见的报错

形状不匹配

报错原文通常是 mat1 and mat2 shapes cannot be multiplied,后面括号里写着 (64x784 and 128x64)。意思是左矩阵 64 行 784 列,右矩阵 128 行 64 列,内维 784 和 128 对不上。两种常见原因:忘了把 28×28 拉平,或者 nn.Linear 的 in_features 写错。修法不是猜,而是在 forward 里打印 x.shape:第一个 Linear 之前必须是 (B, 784),输出必须是 (B, 128)。

拉平的时候注意只动特征维。输入 (64, 1, 28, 28) 用 flatten(1) 得到 (64, 784);若写成 flatten(),64 个样本会被拼成一条 50,176 维的向量,batch 维消失,后面的 Linear 会给出完全错乱的形状。

忘了 zero_grad

梯度会累加。连续 10 个小批量不清零,第 10 步用的梯度是这 10 个小批量的梯度之和,等效学习率放大了约 10 倍。症状是 loss 前期下降很快,随后震荡甚至变成 nan(不是数,not a number)。检查方法很简单:连续两次 backward 之间打印 w.grad.norm(),不清零时它会持续增大,清零后每一步都从头开始。

忘了 model.train() 或 model.eval()

训练时忘了 train(),Dropout 仍处于评估模式,正则化失效,训练准确率虚高;评估时忘了 eval(),Dropout 仍在随机丢激活,同一个样本两次预测不同,验证准确率会抖动 1 到 2 个百分点。更隐蔽的是 BatchNorm:评估时用错统计量,准确率会整体偏低,而且怎么调学习率都救不回来。

设备不一致

报错会以 Expected all tensors 开头,说明模型和数据不在同一台设备上,通常是 cuda:0 与 cpu。统一用 .to(device),并确认 device 变量只定义一次;把设备写死在两个地方,是这类错误的主要来源。

常见误解:backward() 会覆盖上一次的梯度

实际上它做的是累加。同一个参数被多条路径使用时,梯度必须相加才正确,这也是框架默认累加的原因。累加对一次反向是优点,对多次迭代就是坑:不清零,梯度会跨小批量越积越大。所以 zero_grad 不是可选的清理动作,而是训练循环的一部分。

调不通时,先过拟合一个批

取 64 个样本固定不变,训练 100 步,把 loss 打到接近 0。如果做不到,问题在数据、标签或学习率,不在模型容量。这个五分钟检查能排除大多数“训练不收敛”的假象,也能确认 backward 和 step 真的在改参数。

B.10把这本书搬进框架

最后给一条实践路线。先用这本书的 NN.MLP 在一个二维数据集上跑通,确认你理解前向、损失和梯度;再把同一组超参数搬到 PyTorch,用 nn.Linear 重建结构,用 CrossEntropyLoss 和 Adam 替换手写实现。两边损失曲线应当高度接近;如果差很多,通常是学习率、初始化或数据顺序不同,而不是框架有魔法。

再往上走,依次替换四件事:把数据换成 Dataset/DataLoader,把模型换成 nn.Module,把训练循环换成带 train/eval 的模板,把保存换成 state_dict。每一步只改一个变量,出问题时才能定位。等你把这四步都走通,读别人的 PyTorch 项目就不再是从零猜 API,而是能认出每个部分对应书里的哪一章。

最后提醒一句:不要从网上复制一个训练循环就改模型。先让模板在 MNIST 上跑出 97%,再替换数据与网络;基线都跑不通时,换模型只会把问题藏得更深。

还有一类报错值得单独记住:loss 变成 nan。常见原因按概率排,是学习率太大、对 0 取 log、除以接近 0 的数、标签越界。先打印每个小批量的 loss 和输入范围,再降学习率十倍;不要一上来就换优化器。
