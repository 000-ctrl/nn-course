第 06 章 · 核心

训练循环

把前向、损失、反向、更新串成一个循环,并让它稳定收敛。

读前第 05 章的反向传播与梯度;第 03 章的损失函数(MSE/交叉熵)、梯度下降与学习率可跳过6.1 的代码块只演示 API;6.3 的 AdamW/权重衰减推导、6.5 的方差数值推导可跳过,记住“按 fan_in 缩放”即可

会算梯度只是有了零件。真正把网络训练起来,是把取数据、前向传播、算损失、反向传播、更新参数这五个动作串成一个循环,再调好四个开关:损失函数、小批量(mini-batch)大小、优化器、学习率。这一章把这台机器完整装一遍,并用两个能亲手拖动的实验,让你看见每个开关拨错时损失曲线长什么样。

6.1一个循环,五个动作

训练循环(training loop)的结构可以用五行伪代码写完,但每一行都对应一个能单独出错的地方。这五步跑完叫一步(step);把所有训练样本完整过一遍叫一个轮(epoch)。

  1. 取一个小批量(mini-batch)。从训练集里抽 batch_size 个样本。常见值是 32、64、256。
  2. 前向传播(forward pass)。把小批量送进网络,得到每个样本的输出。
  3. 算损失(loss)。用一个数概括这批输出和标签差多远。回归和分类用的不是同一个函数,6.2 节讲。
  4. 反向传播(backpropagation)。从损失往回走,算出每个参数的梯度。
  5. 更新并清零。优化器按梯度改参数,然后 zero_grad()。PyTorch 默认把梯度累加,忘记清零会让第二次迭代的梯度变成第一次的两倍,相当于学习率翻倍,而且越滚越大。

先把“批”这个词说清。batch 指一次前向传播喂进网络的样本集合,按大小分三档:一次吃进全部训练样本叫全量批(full batch),整个训练集只有一个批,每个轮只更新一次;一次只吃 1 个样本叫单样本(stochastic),每看一个样本就更新一次;介于两者之间的叫小批量(mini-batch),通常取 32、64、256。平时说的“batch 大小”指的都是小批量的大小,本章统一叫小批量(mini-batch),代码里的 batch_size 就是它。三者在 60,000 个样本上跑完一个轮的更新次数差别很大:全量批 1 次,小批量 64 是 938 次,单样本 60,000 次。

数字感很重要。在 60,000 个样本上取小批量 64,一个轮是 938 步;跑 30 个轮就是 28,140 次参数更新。每次更新,网络只看 64 个样本。如果改成单样本,同样 30 个轮会更新 1,800,000 次,但每一步的梯度只来自一个样本,方向抖得厉害,GPU 也跑不满。全量批梯度(batch gradient descent)正好相反:每个轮只更新一次,方向很准,但一天也走不了几步。

打乱(shuffle)不是可选项。若数据按类别排序而你不打乱,一个小批量可能 64 个样本全是第 1 类,下一步全是第 2 类,参数被来回猛推。每个轮开始前重新打乱;总随机种子只在训练开始时初始化一次,既避免这种系统性偏置,又让实验可复现。

python
import math, torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(0)
# 3 类螺旋,每类 200 点
t = torch.linspace(0, 1, 200)
X, Y = [], []
for c in range(3):
    a = t * 3.6 * math.pi + c * 2 * math.pi / 3
    r = 0.15 + t * 1.8
    X.append(torch.stack([r * torch.cos(a), r * torch.sin(a)], dim=1))
    Y.append(torch.full((200,), c))
X, Y = torch.cat(X), torch.cat(Y)
loader = DataLoader(TensorDataset(X, Y), batch_size=32, shuffle=True)

model = nn.Sequential(
    nn.Linear(2, 64), nn.ReLU(),
    nn.Linear(64, 64), nn.ReLU(),
    nn.Linear(64, 3),
)                                    # 4,547 个参数
opt = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=1e-2)
sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=30)
loss_fn = nn.CrossEntropyLoss()

for epoch in range(30):
    model.train()
    for xb, yb in loader:            # shuffle=True 每个轮重新打乱
        opt.zero_grad()
        loss = loss_fn(model(xb), yb)
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        opt.step()
    sched.step()                     # 每个轮末降一次学习率
    model.eval()
    with torch.no_grad():            # 评估不建计算图
        acc = (model(X).argmax(1) == Y).float().mean().item()
    print(epoch, round(loss.item(), 4), round(acc, 3))

这段代码里有三个容易漏的细节。model.train() 和 model.eval() 会切换 BatchNorm 与 Dropout 的行为,评估时忘了切,数字会莫名其妙地差一截;with torch.no_grad() 让评估不建计算图,显存少一大半;变量 loss 是最后一个小批量的,不是整个轮的平均,想看真实曲线要自己累加。

6.2损失函数选错,梯度就错了

损失函数(loss function)把“预测得好不好”压缩成一个标量。它的选择不是审美问题:同一个网络,损失选错,梯度就错了,后面换什么优化器都救不回来。

回归:均方误差

预测房价、温度这类连续值时,用均方误差(mean squared error, MSE),其中 Σ 是求和(sum):

L = (1/2n) Σ (pi − yi)²

前面的 1/2 只是为了让求导后少一个因子 2,不影响最优解。平方让正负误差不会互相抵消,也让大误差的惩罚更重:误差 2 的惩罚是误差 1 的 4 倍。开根号得到 RMSE,单位和标签一致,汇报时更好懂。

分类:交叉熵

分类网络的最后一层先输出 K 个得分,叫 logit。softmax 把 logit 变成和为 1 的概率,交叉熵(cross-entropy)只关心正确类别的那个概率:

L = − Σc yc log pc

标签是独热(one-hot)时,求和里只有真实类别那一项非零,所以 L = −log ptrue。代入几个数:p=0.9 时损失 0.105;p=0.5 时 0.693;p=0.1 时 2.303;p=0.01 时 4.605。概率越接近 0,惩罚增长得越快,而且没有上界。

为什么分类不用 MSE

关键不在损失数值,而在梯度。以二分类的 sigmoid 输出为例,记网络输出概率为 p:交叉熵对 logit 的梯度是 p − y;MSE 的梯度是 (p − y) · p(1 − p),多乘了一个饱和因子。真实标签 y=1、预测 p=0.01 时,前者是 −0.99,后者是 −0.99 × 0.0099 ≈ −0.0098,小了 100 倍。预测错得越离谱,梯度反而越小,网络学得越慢,这叫饱和(saturation)。多分类的 softmax 上,交叉熵的梯度仍是 pk − yk;MSE 也带同样的饱和因子,只是每一项还与其他类别的概率耦合,形式更复杂,结论不变。

  • MSE 把 one-hot 当成连续目标回归,隐含“类别之间有距离、有顺序”。对无序类别,这个假设是错的。
  • 按本章公式(带 1/2)对类别求平方和时,每一项最多是 0.5,三分类的总损失封顶 1.5;哪怕网络把 99% 的把握押在错误类别上,也只有 ½[(1−0.01)² + 0.99² + 0²] ≈ 0.98。同一个预测的交叉熵是 −log 0.01 = 4.605,而且随着正确类概率趋近 0 还能继续增大。
  • 交叉熵配上 softmax,梯度形式干净到只剩 p−y,数值稳定,这是它成为分类默认选择的主要原因。
点开看:softmax + 交叉熵的梯度为什么是 p−y

softmax 的定义是 pk = ezk / Σj ezj。对 logit zk 求导,要分 k 是否等于真实类别两种情况,结果是 ∂L/∂zk = pk − yk(∂ 是偏导,partial derivative)。也就是说,每个 logit 收到的推力,正好是“预测概率减标签”。预测 0.01、标签 1,推力就是 −0.99;预测 0.99、标签 0,推力就是 +0.99。框架把 softmax 和交叉熵合成一个算子,就是为了直接得到这个稳定形式,避免先算概率再取对数时的数值问题。

∂L/∂zk = pk − yk

6.3优化器:同一个梯度,三种走法

有了梯度 g,最朴素的更新是梯度下降(gradient descent);这里 θ 是全部参数,η 是学习率,← 表示赋值:

θ ← θ − η · g

η 是学习率(learning rate),g 是损失对参数的梯度。SGD(stochastic gradient descent,随机梯度下降)的毛病是它对所有参数、所有方向用同一个步长。损失面像一个狭长的峡谷时,横跨峡谷的方向很陡,沿谷底的方向很平;同一个 η 在陡的方向来回震荡,在平的方向又走得太慢。

动量(momentum)让梯度先经过一个滑动平均,再拿去更新:

v ← βv − ηg;   θ ← θ + v

β=0.9 时,速度大约记住最近 1/(1−0.9)=10 步的梯度:方向一致的梯度累加,来回变化的梯度互相抵消。效果是在峡谷底部越走越快,横跨峡谷的震荡被压住。

Adam(adaptive moment estimation,自适应矩估计;矩即平均值 moment)再进一步,同时估计梯度的一阶矩和二阶矩:

m ← β1m + (1−β1)g;  v ← β2v + (1−β2)g²;  θ ← θ − η · m̂ / (√v̂ + ε)

m̂ 和 v̂ 是偏差修正后的矩估计。用 √v 去除梯度,等于给每个参数单独缩放:梯度长期很大的参数不会一步跨太远,梯度长期很小的参数也不会被淹没,每个参数的有效步长都接近 η。默认值 β1=0.9、β2=0.999、ε=1e-8,学习率 1e-3。代价是每个参数要多存两份状态,优化器显存约为参数量的 3 倍;有些任务上,精心调过的 SGD 加动量泛化略好。大模型常用 AdamW,它把权重衰减(weight decay)从梯度里拆出来,正则项不再被自适应缩放扭曲。这里容易混淆:权重衰减和 L2 正则只在普通 SGD 下等价——在损失里加 λ‖θ‖²/2(‖·‖ 是向量长度,norm),梯度多出 λθ,每步就变成 θ ← θ − η(g + λθ),与直接按比例缩小权重是同一件事;换成 Adam 后,λθ 被并入梯度再被 √v 自适应缩放,每个参数的实际衰减强度不再一致。AdamW 把它拆出来,直接对参数乘 (1 − ηλ),才是真正的权重衰减。第 7 章讲正则化时会再回到这个区别。

6.4学习率与调度

如果只能调一个超参数,调学习率。它决定每步走多远:太小,参数几乎不动;太大,一步跨过谷底,损失震荡甚至变成 NaN。本章第二个演示用同一个初始化、同一个随机种子、小批量 32,让 Adam 跑 200 步:学习率 0.0001 时损失只从 1.500 降到 1.316;0.05 时降到 0.725;把滑块拉到 1,过程中损失冲到 18.4,最后停在 1.117,比 0.05 差得多。

为什么会有硬上限:把损失面在某点附近近似成曲率为 L 的碗,梯度下降稳定的条件是学习率低于 2/L。超过这条线,每一步把误差放大 |1−ηL| 倍,训练从指数下降翻转成指数上升。深度网络的 L 随位置变化,所以这个上限只能靠实验找,但“损失突然爆炸就先把学习率除以 10”这条经验几乎总是对的。

学习率调度(lr schedule)是在训练过程中主动改变 η,常见三种做法:

  • 阶梯衰减(step decay)。每 30 个轮把学习率乘 0.1。实现最简单,曲线会有明显台阶。
  • 余弦退火(cosine annealing)。按 ηt = ηmin + ½(ηmax − ηmin)(1 + cos(πt/T)) 从峰值平滑降到接近 0,t 是当前步,T 是总步数。前期大步走,后期小步收,不需要猜在哪个轮降。
  • 预热(warmup)。最初 500 步从 0 线性升到峰值。训练初期 Adam 的二阶矩估计还很粗糙,直接上大学习率容易炸。大模型常在 100,000 步里用 2,000 步预热。

6.5权重初始化:不要全零,也不要乱缩放

初始化(weight initialization)决定训练开始时信号有多强。最糟的选择不是随机,而是全零。

假设一个隐藏层有 16 个 ReLU 单元,权重和偏置全 0。输入相同,16 个单元的输出都是 0;反向传播时,输出层的误差要先乘输出层权重才能传回隐藏层,而输出层权重也是 0,所以隐藏层收到的梯度全是 0。这些参数一步都不会更新。输出层自己的权重乘的是隐藏层激活 0,同样不动;只有输出偏置还能改,网络最终退化成一个与输入无关的常数预测器,无论喂什么,三类概率都一样。即使把偏置设成非零,同一层 16 个单元仍会永远收到完全相同的梯度、保持完全相同的参数,16 个单元等价于 1 个。随机初始化首先是用来打破这个对称性的。

但随机的幅度也要对。设每层权重标准差为 s(标准差就是波动的典型大小)、输入维度 fan_in=1024,输出方差约放大 1024·s² 倍(方差是波动的平方,variance)。若 s=1.0,每层放大 √1024=32 倍,10 层就是 3210 ≈ 1.1×1015。这个数本身还没到 float32 的上限(约 3.4×1038),但信号已经放大了 15 个数量级,再深几层、或者换成 float16(上限约 6.5×104),第一次前向就会溢出;若 s=0.01,每层乘 0.32,10 层后只剩 0.3210 ≈ 1.1×10-5,信号缩小到几乎消失——它离 float32 的下溢界限(最小正规数约 1.2×10-38)还很远,但已经比正常输入小五个数量级,激活值会被数值误差淹没。要维持方差,s 应当是 1/√fan_in。ReLU 把一半单元置零,方差再减半,所以 He 初始化用 √(2/fan_in);tanh 和 sigmoid 用 Xavier 初始化 √(2/(fan_in+fan_out))。

PyTorch 里一行就够:nn.init.kaiming_normal_(m.weight, nonlinearity='relu'),偏置置 0。残差连接和归一化让深层网络对初始化的敏感度下降,但“不要全零、按 fan_in 缩放”这两条仍然成立。

6.6梯度消失、梯度爆炸与归一化

梯度消失(vanishing gradient)和梯度爆炸(exploding gradient)来自同一件事:反向传播是雅可比矩阵的连乘。

50 层网络,如果每层把梯度平均缩小到 0.8 倍,传到第一层只剩 0.850 ≈ 1.4×10-5;如果每层放大 1.2 倍,则是 1.250 ≈ 9,100。前者表现为浅层权重几乎不动、只有最后几层在学习;后者表现为损失突然变成 NaN,或者梯度范数达到几千。

对策按成本从低到高:ReLU 代替 sigmoid(正区间导数恒为 1)、He 初始化、残差连接(residual connection,把输入直接加到输出上,给梯度一条短路)、归一化、梯度裁剪(gradient clipping)。裁剪把整个梯度向量的长度缩到不超过阈值,方向不变:若范数是 25、阈值是 1,就整体乘 0.04。

归一化(normalization)把每层输入的尺度拉回可控范围。批归一化(BatchNorm)对一个小批量内同一特征做标准化,再乘可学习的 γ、加 β:

x̂ = (x − μB) / √(σB² + ε);   y = γx̂ + β

训练时 μB、σB 来自当前小批量,推理时用训练期间累计的滑动平均(动量 0.1)。这带来一个限制:小批量太小时统计量不准,只喂 1 个样本直接失效。

层归一化(LayerNorm)对单个样本的所有特征做标准化,与小批量无关。序列长度可变、小批量很小时也能用,所以 Transformer 几乎都用它:GPT-3 有 96 层,每层两个 LayerNorm。一句话区分:BatchNorm 跨样本、同特征;LayerNorm 跨特征、同样本。

常见误解:学习率调大,收敛更快

学习率有硬上限。对曲率为 L 的二次损失,η 超过 2/L 后,每步误差放大 |1−ηL| 倍,训练不是变快,而是从指数下降翻转成指数上升。本章第二个演示里,lr=1 的 Adam 在 200 步内把损失冲到 18.4,最后停在 1.117,比 lr=0.05 的 0.725 差得多。看到损失突然变成 NaN,先把学习率除以 10,不要继续加步数。

省时间的自检:先在一个小批量上过拟合

拿 32 个样本,关掉打乱,训练 200 步,看损失能不能降到 0.01 以下。能,说明前向、损失、反向、更新这条链路是通的,再去调全量数据;不能,问题一定在代码或损失函数里,调学习率没用。

6.7把顺序固定下来

把这一章压成一张操作顺序:

  1. 确定任务,选损失:回归用 MSE,分类用交叉熵;分类模型直接输出 logits。
  2. 按 fan_in 初始化(ReLU 用 He,tanh 用 Xavier),不要全零。
  3. 选优化器:先 Adam、学习率 1e-3;需要榨性能时换 SGD 加动量,配余弦退火。
  4. 小批量取 32–256,每个轮打乱;记录每个轮的平均损失,不是最后一个小批量的。
  5. 先跑 200–500 步看损失是否稳定下降;出现 NaN 就把学习率除以 10。
  6. 深层网络加归一化与残差;梯度范数超过阈值就裁剪到 1.0。
  7. 每个轮末切到 eval 模式评估,不要用训练损失下结论。

这套循环在 4,547 个参数的网络上和在 70 亿参数的模型上是同一个循环,差别只在数据量、并行方式和调度细节。下一章处理循环之外的第一个问题:训练损失很低、测试损失很高,到底发生了什么。
