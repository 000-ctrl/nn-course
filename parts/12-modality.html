一张照片、一句话、一段录音、一段视频,在硬盘上是四种毫不相干的字节。可一旦送进神经网络,它们都必须回答同样三个问题:原始信号怎么切成小块?每一块怎么变成一个向量?这些向量怎么排成一条序列?本章按图像、文本、音频、视频的顺序各拆一遍,再把它们拼回同一个答案。

12.2图像:像素是最直白的张量

图像的张量(tensor)有三个轴:高、宽、通道。224×224 的 RGB 图是 224×224×3,共 150,528 个 0 到 255 的整数。训练前通常除以 255,再按数据集均值方差归一化,把它们变成均值 0、方差 1 的浮点数。PyTorch 默认把通道放在最前面,所以一批 32 张图是 [32, 3, 224, 224]。

CNN(convolutional neural network,卷积神经网络)不改变这个张量的基本形状,而是用很小的卷积核在上面滑。一个 3×3 的 RGB 卷积核只有 3×3×3=27 个权重加 1 个偏置;同一个核在 224×224 个位置上复用,这就是参数共享。它带来的先验是:猫的耳朵出现在左上角还是右下角,都应该被同一个检测器认出来。

2012 年的 AlexNet 有 8 层、约 6,000 万个参数,把 ImageNet 1,000 类的 top-5 错误率从 26.2% 降到 15.3%。它的第一层卷积核学到的是边缘和色块,最后一层才是类别。这个“从局部纹理到整体物体”的层级,是 CNN 最核心的归纳偏置(inductive bias)。

ViT(vision transformer)把这件事换了个做法。它不做卷积,而是把图切成固定大小的 patch(图像块)。224/16=14,于是得到 14×14=196 个 16×16 的块;每块拉直成 16×16×3=768 个数,过一个线性层变成 dmodel 维 token(ViT-B/16 取 768,输入和输出恰好同宽;ViT-L/14 的 patch 输入是 14²×3=588,dmodel 另设为 1,024)。再加上位置编码,196 个 token 一起送进 Transformer。序列长度只有 196,自注意力的 196×196 相似度矩阵完全算得动。

N = (H/p) × (W/p),  dpatch = p2C,  dmodel = 超参

N 是 patch 数,dpatch 是每个 patch 拉直后的输入长度(p²C),线性层把它映射到 dmodel 维的 token。切得越细,token 越多、每个 patch 的输入越短。224 的图、16 像素的块,N=196,dpatch=16²×3=768;换成 8 像素的块,N 变成 784,dpatch 只剩 8²×3=192。但 dmodel 是另一个超参,不随 patch 大小变:ViT-B/16 取 768,ViT-L/14 取 1,024;把代码里的 kernel 改成 8,Conv2d 的输出仍然是 768 维。

python
import torch, torch.nn as nn

# 224x224 RGB -> 14x14 = 196 个 patch,每个 768 维
to_patch = nn.Conv2d(3, 768, kernel_size=16, stride=16)
x = torch.randn(8, 3, 224, 224)          # 一个 batch 8 张图
tokens = to_patch(x).flatten(2).transpose(1, 2)
print(tokens.shape)                       # torch.Size([8, 196, 768])

pos = nn.Parameter(torch.zeros(1, 196, 768))
tokens = tokens + pos                     # 位置编码;否则打乱 patch 顺序,结果完全一样

切法一变,代价立刻显现。1080p 画面是 1920×1080,按 16×16 切是 120×67.5,取整后 120×68=8,160 个 token;token 数是 224 图的 41.6 倍,注意力矩阵是 1,733 倍。这就是为什么高分辨率图像和视频模型要把 token 合并、剪枝,或者改用窗口注意力。

12.3文本:token 是离散的符号

第 10 章 10.6 只用一句话带过 BPE:从字节出发,反复合并高频的相邻片段。这一节把它讲完整。文本的处理从分词(tokenization)开始,模型只认整数,不认字符。BPE(byte pair encoding,字节对编码)是一种字节级的合并算法,所以又叫 byte-level BPE(字节级 BPE):先把文本按 UTF-8 写成字节,起点是 256 个可能的字节值,不是几万个汉字。常用汉字在 UTF-8 里占 3 个字节,“神”一开始是 3 个整数;这样任何字符串都表示得出来,不会出现词表外的字符(out-of-vocabulary,OOV)。

合并怎么走?每轮统计语料里相邻两个 token 一起出现的次数,把最高的一对粘成新 token,写进词表;重复几万轮,词表就从 256 长到几万。举个小例子:语料里 low 出现 5 次、lower 出现 2 次、lowest 出现 2 次,先全部拆成字节。第一轮 (l,o) 出现 9 次,(o,w) 也出现 9 次,并列最高;实现里按固定顺序打破平局,这里假设先选 l+o,合成 lo。第二轮 lo+w 出现 9 次,合成 low。此后 low 在三个词里都是一个 token,lower 只剩 low+e+r。

(a,b) = argmax(a,b) count(a,b)

每轮在语料的所有相邻对里,选出出现次数最多的那一对 (a,b),合并成一个新 token。count 是这一对在全部字节序列里相邻出现的次数。

训练结束后留下的是有序的合并规则,不是统计表。编码新句子时,同样先转成字节,再按学到的顺序逐条套用合并规则——顺序不能乱,先学的规则优先级高。GPT-2 的词表 50,257 = 256 个字节 + 50,000 条合并 + 1 个文本结束符;Llama 3 的词表是 128,256。词表越大,常见片段越少被拆开,同样一句话的 token 数越少,但输出层的矩阵也越大。

分词结果直接决定成本。英文平均一个 token 约 4 个字符,1,000 个单词的文章大约 1,300 个 token;中文常用词经常被切成 1 到 3 个 token,30 个汉字可能是 30 到 45 个 token。上下文长度 8,192 的意思不是 8,192 个汉字,而是 8,192 个 token。

每个 token id 去查一张 embedding(嵌入)表。表是 [词表大小, d_model] 的矩阵,一行就是一个 token 的向量。GPT-3 的 d_model=12,288、词表 50,257,光这张表就有 50,257×12,288=617,558,016 个参数,约 6.18 亿;模型总共 1,750 亿参数,嵌入只占 0.35%。

然后就是 Transformer:每个位置的向量经过多层自注意力(self-attention),和序列里其他位置交换信息。训练目标是预测下一个 token,损失是 50,257 类上的交叉熵。文本最特殊的地方在于它是离散的:像素加 1 还是像素,采样点加 1 还是声音,但 token id 加 1 可能从“猫”跳到“汽车”。所以文本必须先查表变成连续向量,梯度才能定义。

P(xt | x<t) = softmax(W ht)

给定前 t−1 个 token 的隐藏状态 h,用一个 [词表大小, d] 的矩阵算出每个候选 token 的分数,softmax 变成概率。训练时最大化正确 token 的概率,推理时按这个分布采样。

12.4音频:一秒一万六千个点

声音是空气压强随时间的连续变化。模数转换器每秒钟量 16,000 次,每次存一个 -1 到 1 的浮点数,这就是 16 kHz 采样。一秒 16,000 个数,一分钟 96 万个;音乐常用的 44.1 kHz 一分钟是 264.6 万个。

直接把波形喂给网络有两个困难。第一是长度:16,000 个点,就算第一层把长度减半,也要 14 层才能把感受野做到 1 秒。第二是相位:人耳对相位差不敏感,两个相位不同的波形听起来可以一样,但逐点相减差别巨大;网络却要为这些听不出来的差异浪费容量。

所以大多数音频模型先做 STFT(short-time Fourier transform,短时傅里叶变换):每 25 毫秒取 400 个采样点,乘窗,做快速傅里叶变换(FFT),得到这一小段的频率成分;窗每 10 毫秒滑动一次,也就是每秒 100 帧。再把频率轴按梅尔刻度(mel scale)压成 80 个 bin,取对数,得到 log-mel 频谱。一秒语音从 16,000 个数变成 100×80=8,000 个数,而且每一列直接告诉你“这 10 毫秒里有哪些频率、各有多响”。

X(m,k) = Σn=0N−1 x(n+mH) w(n) e−i2πkn/N

先认符号:Σ 是求和,e 是自然常数,i 是虚数单位,π 是圆周率,e−i2πkn/N 是第 k 个频率的旋转因子。m 是第几帧,H 是帧移(这里 160 个采样点,即 10 毫秒),k 是频率编号。每个 m 做一次 FFT,就得到一列频谱;把所有列并排,就是语谱图。梅尔刻度用 m = 2595·log10(1+f/700) 把线性频率压成更接近人耳的非线性刻度。

python
import torch, torchaudio

wav, sr = torchaudio.load("speech.wav")   # 1 秒,16 kHz,形状 [1, 16000]
mel = torchaudio.transforms.MelSpectrogram(
    sample_rate=16000, n_fft=400, hop_length=160, n_mels=80
)(wav)
logmel = torch.log(mel + 1e-6)
print(logmel.shape)                       # [1, 80, 101],约 100 帧/秒

具体到模型:Whisper 的编码器吃 30 秒音频,先算 80 通道 log-mel,得到 3,000 帧;前端两层卷积把步长降 2,变成 1,500 个位置,再进 Transformer。wav2vec 2.0 反过来直接吃原始波形,用 7 层卷积把 16,000 Hz 降到 50 帧/秒,再对量化后的离散单元做对比学习,不需要文字标注。TTS(text-to-speech,语音合成)则倒着走:Tacotron 2 从文字预测 80 维 mel 帧,再用 WaveNet 声码器(vocoder)把 mel 还原成 24 kHz 波形;VITS 把两步合成一个网络。

更新的做法把音频也离散化。神经音频编解码器(neural audio codec)把 24 kHz 波形压成每秒 75 帧、每帧 8 个码本(码本是一张固定向量表,codebook),合计约 600 个 token/秒:EnCodec 在 6 kbps 下正是 8 个码本、每秒 75 帧,每个码本 1,024 项,8×75×10 bit≈6,000 bit/s。这样音频和文字一样,变成语言模型可以直接预测的整数序列。

一段 1 秒、16 kHz 的语音,直接喂原始波形和喂 80 维 log-mel 频谱,最主要的区别是什么?

12.5视频:帧序列加一根时间轴

视频是一叠图像加一根时间轴。30 fps 意味着一秒 30 张 1920×1080 的图;一帧 622 万个数字,一秒 1.87 亿个,一分钟 112 亿个。没有人会逐像素处理一分钟的原始视频,所以视频模型的第一步永远是抽帧和降分辨率。

3D CNN 把卷积核从二维扩到三维:一个 3×3×3 的核一次看 3 帧、3 行、3 列。Two-Stream 网络把 RGB 帧和光流(optical flow)分成两条路,光流显式编码相邻帧之间的运动。SlowFast 用两条采样率不同的路径:慢路径每 16 帧取 1 帧看颜色和场景,快路径每 2 帧取 1 帧看动作;在 64 帧的片段里,两条路径分别只有 4 帧和 32 帧。

Video Transformer 把视频切成 tubelet(时空小管)。TimeSformer 默认每 1 帧取一个 16×16 的块,拉平成 1 个 token:8 帧、每帧 14×14=196 个 patch,一共 8×196=1,568 个 token。也可以让一个 tubelet 横跨 2 帧(t=2),token 数减半到 784,代价是每个 token 要把两帧的同一位置一起编码。TimeSformer 把注意力拆成时间注意力和空间注意力两段,避免让 1,568 个 token 两两全连接;全时空注意力是 1,568²≈246 万对,分开以后,空间段每帧只在 196 个 patch 内算,时间段只在 8 个位置之间算。

Nvideo = (T/t) × (H/p) × (W/p)

t 是 tubelet 的时间跨度,p 是空间 patch 的边长。TimeSformer 默认 t=1,即每帧单独切:8 帧、每帧 14×14 个 16 像素 patch,就是 (8/1)×14×14=1,568 个 token。若把连续 2 帧拼成一个 tubelet(t=2),token 数减半,变成 784。时间轴每多一倍,序列长度就多一倍。

抽帧是最先被砍的预算。1 分钟 30 fps 是 1,800 帧,按 2 fps 抽只剩 120 帧,每 8 帧装一个 clip,只剩 15 个 clip;如果一帧不抽,1,800 帧要装 225 个 clip,每个 1,568 个 token,一分钟就是 352,800 个 token。这个数字比很多语言模型的上下文还长,所以长视频理解至今是工程问题,不只是模型问题。

交互30 fps 如何被抽成稀疏帧拖动滑块
上排是 30 fps 的源视频(1 秒),下排是按当前帧率抽出的帧。滑块拖到 30 时一帧不丢;拖到 1 时只剩 1 帧,但每帧仍是 64×64×3 个数,堆成的张量第一维就是帧数。

12.6多模态对齐:CLIP 把两种语言放进同一个空间

多模态(multimodal)模型的第一道关,是把两种完全不同的输入放进同一个向量空间。图像编码器输出一个 768 维向量,文本编码器也输出一个 768 维向量。两个向量怎么判断配不配?CLIP(contrastive language-image pre-training)的答案是:让配对的靠近,不配对的远离。

训练数据是 4 亿个(图像, 文本)对。一个 batch 取 32,768 对,两个编码器各算出 32,768 个向量,做 L2 归一化,再算一个 32,768×32,768 的余弦相似度矩阵(余弦相似度=两向量夹角的接近程度,cosine similarity)。对角线是正确配对,其余约 10.7 亿个格子都是负样本。损失函数只做一件事:让每一行的最大值落在对角线上。

L = −(1/N) Σi log [ exp(sim(ii,ti)/τ) / Σj exp(sim(ii,tj)/τ) ]

sim 是余弦相似度,i_i 是第 i 张图的向量,t_j 是第 j 句文本的向量。分子是正确配对,分母是这一行所有配对之和。τ 是可学习的温度(temperature),CLIP 初始化成 0.07;τ 越小,softmax 越尖锐,模型越只盯最像的那一个。

这个目标叫对比学习(contrastive learning),损失函数叫 InfoNCE。它不需要给图像打 1,000 类标签,也不需要生成描述,只需要“这一对是真的,其他都是假的”。正因为监督信号是相对的,CLIP 才能把任意一句描述和任意一张图放进同一个空间比较。

零样本(zero-shot)分类是它的直接用法:把 1,000 个类名写成“一张{类名}的照片”,编码成 1,000 个文本向量;图像向量和它们算余弦相似度,取最大的那个。ViT-L/14@336px 在 ImageNet 上零样本 top-1 达到 76.2%,训练时没有见过 ImageNet 的任何一张图。

后来的多模态模型大多站在这个接口上。Stable Diffusion 用 CLIP 的文本编码器把提示词变成 77 个 token;LLaVA 用一个线性层把 ViT 的 576 个图像 token 投影到语言模型的词向量空间,和文字 token 拼成一条序列,送进同一个 Transformer。SigLIP 把 softmax 换成 sigmoid,不再需要整个 batch 的全局归一化,训练更省内存。

常见误解

多模态模型不是先把图像“翻译成文字”再交给语言模型。CLIP 对齐的是连续向量;LLaVA 投影的是 576 个连续图像特征。把图像写成一句描述,会丢掉 15 万个数值里的绝大多数信息。文字是对齐时的监督信号,不是推理时的中间格式。

交互一句话如何在嵌入空间里找到图点选句子
左边是 2 维投影后的图像向量(方块)和文本向量(圆圈),右边是当前句子的余弦相似度。点不同的句子,看哪张图被排到第一。真实 CLIP 是 512—1,024 维,这里只是为了画得下。

12.7一切都在变成 token

把四条流水线并排看,最后一步的形状完全一样:一个 [N, d] 的矩阵,外加位置信息。Transformer 不关心第 3 个 token 来自 16×16 的图像块、一个汉字、10 毫秒的音频,还是视频里的一小块时空;它对所有 token 做同一件事:让它们互相交换信息。

这就是“一切都在变成 token”的真正含义。图像用 patch token;矢量量化变分自编码器(VQ-VAE)进一步把每个 patch 量化成码本表里 256 个条目中的一个编号,一张 256×256 的图变成 32×32=1,024 个离散 token;音频用神经编解码器变成每秒 75 帧、每帧 8 个码本(约 600 个 token/秒);视频用 tubelet token;文本本来就是 token。模态的差异被推到了最前面的 tokenizer,后面的网络可以共享。

代价同样直接:token 数就是计算量。注意力是 O(N²),N 从 196 涨到 8,160,矩阵乘法涨 1,733 倍;视频一分钟 352,800 个 token,没有分块、稀疏注意力或线性注意力根本跑不动。所谓多模态大模型的工程,一大半在回答:怎么用更少的 token 保留更多的信息。

核心结论

模态决定 tokenizer,不决定 Transformer。拿到一个新模态,先数它的原始序列长度,再决定切多细、用什么表示,最后才是选网络结构。
